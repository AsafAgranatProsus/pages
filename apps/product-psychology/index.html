MODULE 1 · WEEK 1

Understand User Behaviors

Three mental models that explain almost every "why did the user do that?" moment.
Learn

System 1 vs System 2

Lesson 1.1 · Kahneman

Kahneman's Thinking, Fast and Slow splits cognition into two systems. System 1 is fast, automatic, emotional, pattern-matching — it runs almost all of your product's moment-to-moment decisions (which button to tap, whether to trust a screen). System 2 is slow, effortful, deliberate — it only engages when System 1 flags something as unusual, risky, or worth real thought.

  • Most UI decisions are made by System 1 in under a second
  • System 2 is lazy — it defers to System 1 whenever it can
  • Friction, ambiguity, or a broken pattern is what wakes System 2 up

Product implication: if a screen requires System 2 thinking to complete a routine task, you've made a design error, not a user-education problem.

The Fogg Behavior Model

Lesson 1.2 · BJ Fogg

Behavior happens when three things converge at the same moment: B = MAP

Motivation — how much the person wants the outcome right now
Ability — how easy the action is (time, money, effort, brain cycles, social deviance, routine)
Prompt — the trigger that asks for the behavior at that moment

If a user doesn't act, one of the three is missing — and the highest-leverage fix is almost always Ability (make it easier), not motivation (nagging harder).

The Hook Model

Lesson 1.3 · Nir Eyal

Eyal's Hooked describes how habit-forming products close a loop: Trigger → Action → Variable Reward → Investment.

  • External trigger (notification) fades as an internal trigger (boredom, anxiety, FOMO) takes over
  • Variable reward — unpredictable payoff (like/comment count, feed content) keeps dopamine engaged
  • Investment — the user puts in effort (data, content, followers) that increases the odds they return

Ethical flag: this same loop underlies both genuinely useful habits (language learning) and manipulative engagement traps (infinite scroll). Module 5 gives you the test to tell them apart.

Practice
A user abandons a signup form at the "upload ID document" step. Using B=MAP, what's most likely missing?
Ability is almost always the answer for a mid-onboarding drop-off after the user has already invested steps — motivation was clearly present, and the prompt is right in front of them. The fix is reducing effort (allow "finish later," auto-crop the photo, explain why it's needed right at that step) — not motivational copy.
Which System is responsible for a user hesitating and re-reading a confirmation dialog twice before clicking "Delete"?
Irreversibility and risk are exactly the triggers that escalate a decision from System 1 to System 2. This is by design in good product work — you *want* System 2 engaged before a destructive, unrecoverable action.
Apply

Exercise 1 — Run B=MAP on your own product

Pick one screen or flow in something you're actually working on (Toqi, the karate site, anything real) where users drop off or hesitate.

  1. Name the specific behavior you want (the action, precisely)
  2. Rate Motivation at that moment (low/med/high) and why
  3. Rate Ability — what's the single hardest sub-step?
  4. Check the Prompt — is it present, and does it arrive at the right moment?
  5. Write the one change you'd make first

MODULE 2 · WEEK 2-3

Find The Gaps & Improve Any Experience

Know which psychology principle explains a friction point, and which one fixes it.
Learn

Heuristic Evaluation

Lesson 2.1 · Nielsen Norman

Jakob Nielsen's 10 usability heuristics are the fastest way to grade any screen without user testing. The five that catch the most real-world gaps:

  • Visibility of system status — does the user always know what's happening?
  • Match with the real world — does it speak the user's language, not the system's?
  • User control & freedom — is there an obvious "undo" / exit?
  • Recognition over recall — is the needed info visible, not memorized?
  • Error prevention — does the design stop mistakes before they happen?

Cognitive Load & Friction

Lesson 2.2

Every extra decision, field, or unfamiliar pattern taxes a limited pool of mental effort (working memory). Friction isn't always bad — sometimes it's a deliberate System-2 speed bump (Module 1). The skill is telling accidental friction (a gap to close) from intentional friction (a safeguard to keep).

Diagnostic question: does this step protect the user or the business from a real risk? If no — it's a gap.

Cialdini's Influence Principles

Lesson 2.3 · Robert Cialdini

Six principles that predict what moves people to say yes — useful both for spotting why an experience under-converts and for designing an ethical fix:

Reciprocity — give first (value, information) before asking
Commitment & Consistency — small yeses make bigger yeses easier
Social Proof — "people like me are doing this"
Authority — credible signals reduce decision anxiety
Liking — familiarity and similarity lower resistance
Scarcity — perceived limits raise perceived value

The Gap-Finding Framework (this course's B.I.A.S.-style tool)

Lesson 2.4 — worked method

For any screen or flow, run this 4-step grading pass:

  1. Behavior — what does the user actually do here (not what you intended)?
  2. Interruption — where do they hesitate, re-read, back out, or abandon?
  3. Assumption — what did the design assume the user already knows or wants?
  4. Signal — which heuristic or influence principle is violated at that exact point?

This is the reusable diagnostic — Module 3 uses it at the journey level, Module 4 uses it to justify a fix to stakeholders.

Practice
A checkout page shows "Only 2 left in stock!" — which Cialdini principle is this, and is it always manipulative?
Scarcity is ethically neutral in itself — the test is truthfulness (Module 5's manipulation matrix). A real low-stock count helps a genuine decision; a fake countdown timer that resets on refresh is a dark pattern.
Users keep tapping a greyed-out button expecting it to work. Which heuristic is violated?
A disabled button with no explanation leaves the user guessing at system state. The fix isn't just "enable it" — it's telling the user exactly what condition unlocks it.
Apply

Exercise 2 — Run the Gap-Finding Framework

Take the same screen from Exercise 1, or a new one.

  1. Write down the Behavior you actually observe or expect
  2. Name the Interruption point precisely
  3. State the Assumption the design is making
  4. Name the Signal — which heuristic or Cialdini principle is being violated

MODULE 3 · WEEK 4

Create Delightful Journeys

Find the moments worth the most ROI, then reorder the journey around them.
Learn

The Peak-End Rule

Lesson 3.1 · Kahneman

People don't remember an experience as an average of every moment — they remember (and judge) it almost entirely by its most intense point (peak) and its final moment (end). Everything in between is compressed or forgotten.

Product implication: you get outsized ROI from investing in one great peak moment and a strong closing moment — polishing the entire middle of a journey evenly is often wasted effort.

Four Types of Journey Moments

Lesson 3.2
First impressions — sets the trust baseline (halo effect: a good first moment biases perception of everything after)
Friction points — where drop-off/frustration concentrates
Peaks — the highest-emotion moment, positive or negative
Endings — the last thing felt before leaving (recency-weighted, per peak-end)

Journey Mapping Pitfalls

Lesson 3.3

Common failure modes when mapping a journey:

  • Mapping the intended flow instead of the actual one users take
  • Treating every step as equally important (peak-end says they aren't)
  • Building the map once and never updating it as the product changes
  • Mapping in isolation without cross-functional input (support tickets are journey data too)
Practice
Per peak-end rule, where should you invest disproportionate design effort in a 6-step onboarding flow?
Peak-end predicts users will judge and remember the whole flow based on its peak and its end — even if 4 of 6 steps were mediocre, a strong peak + strong ending can carry the overall impression.
Apply

Exercise 3 — Map one real journey

Pick a journey you know well (onboarding, first purchase, first week of use).

  1. List 5-8 real steps (not idealized ones)
  2. Mark the first-impression moment, the peak, and the ending
  3. Identify which one is currently weakest
  4. Write one change that would strengthen it

MODULE 4 · WEEK 5

Communicate Product Decisions

Rally your team and stakeholders around the psychology-backed call, not just your taste.
Learn

Evidence Beats Opinion

Lesson 4.1

"I think this looks better" loses to "users hesitate here because of X heuristic, and here's how competitor Y solved it." Naming the specific mechanism (loss aversion, recognition over recall, peak-end) converts a taste argument into a falsifiable claim — which is exactly what a skeptical stakeholder can actually engage with.

Framing & Loss Aversion in Pitches

Lesson 4.2 · Kahneman & Tversky

People weigh losses roughly 2x more heavily than equivalent gains (Prospect Theory). "This change adds 3% conversion" lands weaker than "this friction point is currently losing you 3% of every cohort." Same fact, framed as a loss — more persuasive, and also more honest about the status quo cost of inaction.

The 3-Step Response Framework

Lesson 4.3 — worked method

For answering any pushback on a design decision:

  1. Acknowledge the concern specifically — restate it so they know you heard it
  2. Name the mechanism — the psychology principle or user data behind your call
  3. Offer the test — "here's how we'd know if I'm wrong" (a metric, a user test)
Practice
A stakeholder says "just add more fields to capture more data, users won't mind." What's the strongest psychology-backed pushback?
Naming the exact mechanism (Ability in B=MAP) and grounding it in an observed pattern turns a taste disagreement into a testable claim — much harder to wave away than a personal preference.
Apply

Exercise 4 — Draft a stakeholder response

Think of a real pushback you've gotten (or expect to get) on a design decision.

  1. Write the pushback verbatim
  2. Acknowledge it in one sentence
  3. Name the specific mechanism/principle backing your call
  4. Propose the test that would prove you right or wrong

MODULE 5 · WEEK 5

Create Ethical & Humane Products

The same psychology principles that delight can manipulate. Here's the test that tells them apart.
Learn

The Manipulation Matrix

Lesson 5.1

Two axes decide whether a persuasive technique is ethical: does it serve the user's genuine interest, and is it transparent (would the user be upset to learn how it works)?

Serves user + transparent → good persuasion (a real progress bar, honest social proof)
Serves user + hidden → paternalistic but usually low-harm (a default set to the statistically best option)
Serves business only + transparent → aggressive but disclosed (a visible ad, an upsell you can decline)
Serves business only + hidden → manipulation (fake urgency, confirmshaming, hidden costs) — this is the zone to design out of your product

Dark Patterns / Deceptive Patterns

Lesson 5.2 · Harry Brignull

Named, catalogued manipulation techniques — knowing the names makes them instantly spottable:

  • Confirmshaming — "No thanks, I don't want to save money"
  • Roach motel — easy to get in, deliberately hard to get out (cancel subscription flows)
  • Sneak into basket — pre-checked add-ons at checkout
  • Fake urgency — countdown timers that reset or aren't real
  • Privacy Zuckering — confusing settings that trick you into sharing more than intended

Three Humane Design Principles

Lesson 5.3 · Center for Humane Technology
Respect attention — design for the user's stated goal, not maximum time-on-app
Respect autonomy — make the "no" or "not now" path as easy to find as the "yes"
Design for long-term wellbeing — optimize for a metric that would still make you proud in 5 years, not just this quarter's engagement number

Ethical Design Checklist — run before shipping any persuasive pattern

Practice
A cancel-subscription flow requires calling a phone number during business hours, while signup takes one click. What's this called, and which matrix quadrant is it?
This is the textbook "roach motel" dark pattern — asymmetric friction between entering and exiting a commitment. It fails the exit-parity test in the ethical checklist above.
Which of these is an example of ethical persuasion, not manipulation?
The genuine, real-time inventory count is truthful and serves the user's actual decision — it passes both the transparency and user-interest tests. The other two are classic dark patterns (fake urgency, sneak-into-basket).
Apply

Exercise 5 — Audit one of your own patterns

Pick one persuasive technique already in a product you work on (a default, an urgency message, a nudge).

  1. Name the technique
  2. Run it through the Manipulation Matrix — which quadrant?
  3. Run the 5-point ethical checklist above against it
  4. If it fails any check, write the fix

Cheat Sheet — All 5 Modules

1 · Understand Users

Mental models
  • System 1 (fast/automatic) vs System 2 (slow/deliberate)
  • B = MAP — Behavior needs Motivation + Ability + Prompt together

2 · Find The Gaps

Diagnostic tools
  • Nielsen's heuristics: status visibility, real-world match, user control, recognition, error prevention

  • B-I-A-S pass: Behavior → Interruption → Assumption → Signal

3 · Delightful Journeys

Journey design
  • Peak-end rule — people judge by the peak + the ending, not the average
  • Four moment types: first impressions, friction points, peaks, endings
  • Map the real journey, not the intended one

4 · Communicate Decisions

Stakeholder framing
  • Name the mechanism, not just your opinion
  • Loss framing outweighs gain framing ~2x (loss aversion)
  • 3-step response: Acknowledge → Name the mechanism → Offer the test

5 · Ethical Design

The line not to cross
  • Manipulation Matrix: user-interest × transparency
  • Dark patterns: confirmshaming, roach motel, sneak into basket, fake urgency, privacy Zuckering
  • 5-point checklist: explainability, exit parity, factual claims, user vs business goal, "would I show my family"
